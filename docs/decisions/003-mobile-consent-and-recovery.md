# ADR-003：手机端分享确认与本机恢复

日期：2026-10-05。状态：已实施；平台验证见阶段记录。

## 问题与选择

第三款的页面仍可能调整，但“日记默认私有、分享需明确选择、失败后不误发”必须保持稳定。
采用 Flutter domain / application / data / presentation 分层，页面不拼 HTTP 地址或直接读写本机数据库。
延用已验证的 Sembast 工作副本与平台安全会话存储，在本仓库维护独立工程和构建脚本。

首页区分自己的日记和虚构角色。日记详情逐个角色显示分享状态；分享前说明对象与影响，撤回不默认勾选重新分享。
读不全授权列表或请求失败时显示未知/错误，不把失败当成“未分享”。修改原文后重新读取分享状态。
查询旧分享请求的结果时，以服务器当前状态为准，不因重试旧操作把已撤回的日记重新分享。

文本输入按账户保存在本机，写请求的原始内容和幂等键先落盘再发送。响应未知时锁定原请求，保留复制与返回入口；
重开后由用户重试原请求，不自动发出分享或消息。版本冲突先比较双方内容，再由用户明确选择。
若创建响应丢失后云端记录被另一端更新，重放会返回当前记录；客户端不能把本机旧输入当作已同步，须进入同样的差异处理。

模型能力由后端 capabilities 控制。未配置或无法确认可用时，生成和发送入口不发请求，输入仍可保留本机。
角色日记标明虚构，空列表不添加假内容。历史失败任务使用稳定错误码说明原因，重试须明确点击且后端仍会复核可重试性。
页面仅在可见且应用前台时刷新任务，离开或切后台停止；恢复后读取持久任务状态。首版不提供后台主动通知。

生成与重试新任务前再查询能力；恢复结果不明的旧请求则继续用原幂等键，即使此时模型已停用。
这是为了确认已经发生过的操作，不是绕过停用状态发起新任务。撤回请求重放展示后端当前授权，不宣称旧操作再次执行。
服务端确认成功而本机清理失败时，保留原始请求和输入，不能先显示“已同步”后又丢失恢复线索。
手机端记忆从某篇已分享日记创建，使用来源版本；不让用户填写内部 ID，编辑页可修正文案或停用。

继续使用手写 HTTP 适配器并以真实 API 测试校验当前契约，避免本阶段增加生成器工具链。
Windows 原仓库包含中文路径，Android 构建使用带哈希清单的临时物理副本；目录链接不足以解决 Gradle 路径检查。

## 代价与验证

本机副本不是完整离线同步；会话令牌使用系统安全存储，草稿数据库未额外加密。
授权状态读取依赖网络；明确失败比显示错误的隐私承诺更重要。
验证写盘失败、响应丢失、重放返回较新内容、撤回与旧请求重试、跨账户隔离、分页授权和迟到请求；
另用真实 API、Android 模拟器和普通安装包验证核心流程。iOS 需后续 macOS / Xcode 验收。
