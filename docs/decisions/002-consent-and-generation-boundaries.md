# ADR-002：分享授权、上下文与生成任务

日期：2026-10-05。状态：已实施，验证结果见阶段记录。

## 问题

日记会修改，分享可撤回，模型请求又可能跨越这些变化。只在页面隐藏内容或在提交任务时检查一次，
不能保证私人记录不发送、撤回后的结果不继续发布。服务商尚未确定，也不能把示例回复当作真实 AI。

## 选择与原因

延续独立 NestJS / TypeScript + PostgreSQL 后端，复用本地已验证的账户和开发数据库基础代码，
在本仓库维护独立副本、端口和运行数据，不跨仓库导入业务代码。

用户日记默认私有；授权绑定“指定日记版本 + 指定角色”。修改已分享日记会撤回旧授权，
新版本需重新分享，避免用户后加的私人内容在不知情时发送。授权修改也要求 revision，防止两端相互覆盖。

每个角色维护上下文代次。角色设定变更、授权变更、相关原文修改、记忆修正或失效会推进代次。
后续上下文只使用当前仍获授权的日记、有效来源的记忆和当前代次的对话/角色日记。
旧对话和虚构日记仍可由用户阅读，但不自动回流到模型。代价是撤回一篇记录会保守地切断该角色的旧对话背景；
首版优先保证不通过摘要或历史回复间接带回撤回内容，后续可用完整来源依赖图改善连续性。

生成任务先持久化，worker 在发送前重新构建获准上下文，结果提交前再次检查代次和任务状态。
网络调用不占数据库事务；撤回可立即完成，正在生成的旧结果随后作废。已经发往服务商的内容无法追回。
写入用账户级事务锁串行化，覆盖授权、幂等回执和结果发布；首版牺牲同账户写并发换取清晰一致的边界。

供应商通过服务端 ModelProvider 接口注入；默认 disabled 返回明确不可用状态，不生成假回复。
测试使用可控适配器验证请求内容、延迟、失败和撤回竞态，不代表已接入真实模型。
任务超时/进程中断标记失败，用户明确重试；不自动重新发送不确定的外部请求，避免意外重复费用。
同一会话一次只有一项待处理回复，同一角色一次只有一项待处理日记。执行标识防止过期 worker 发布结果。
旧失败轮次已有后续消息时拒绝重试，避免给更早的问题插入一条位置错误的回复。

幂等键与请求摘要、资源标识一起提交。相同请求重放返回资源当前状态，不重复执行；
尤其不能因为重试旧“分享”请求而重新授权已撤回的日记。请求摘要按键排序，JSON 字段顺序不影响重试。
列表采用有作用域的游标；消息按明确序号排列，即使同毫秒创建也有稳定顺序。

上下文按最多 48000 个 Unicode 码点分配文本预算，优先当前消息和主动选中的记录，再选近期历史、获准日记与记忆。
普通日记正文最多截取 8000 个码点、旧对话每条最多 4000；这是服务商未定时的本地字符预算，不宣称是模型 token 预算。
较早的关联日记必须显式加入，不能只依赖“最新五篇”的候选集合。任务保存直接引用的日记标识/版本，
并用角色上下文代次处理间接历史依赖；未实现完整的逐句来源图或向量检索。

记忆首版是用户可查看、修正和失效的来源摘要，必须引用当前获准的日记版本；不承诺自动记忆、永久准确。
角色日记始终标记为角色设定内的虚构内容，读取不会触发生成。后台主动消息和定时生成不在本阶段实现。

## 验证

用真实 PostgreSQL 和 HTTP 验证账户/角色隔离、默认私有、修改后重新授权、幂等重试、并发冲突、
撤回前后上下文、生成中的撤回、过期任务恢复、失败回滚、重启持久化与 OpenAPI 一致性。
验证结果、未实现项及远端提交在阶段记录中如实更新。
